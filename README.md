# Corrosion Detection & Classification (YOLO11-seg)

Instance segmentation pipeline that detects steel corrosion in images and
video and classifies each detected region by severity (**fair**, **poor**,
**severe**), using a YOLO11 segmentation model fine-tuned on the Virginia
Tech Corrosion Condition State dataset.

## Dataset

This project uses the **Corrosion Condition State Semantic Segmentation
Dataset** published by Virginia Tech:

> Bianchi, E., and Hebdon, M. (2021). *Corrosion Condition State Semantic
> Segmentation Dataset*. University Libraries, Virginia Tech.
> https://doi.org/10.7294/16624663

The dataset was collected from Virginia Department of Transportation (VDOT)
bridge inspection reports and semantically annotated following the
corrosion condition state guidelines from AASHTO and the Bridge Inspector's
Reference Manual (BIRM). It defines four severity classes (*good, fair,
poor, severe*), with 440 finely annotated images (396 train / 44 test),
resized to 512x512. The dataset authors reported an F1 score of 86.67 using
a DeepLabV3+ model — see the dataset page for details and the associated
journal article.

This project only trains on three of the four classes present in the
dataset masks — **fair, poor, severe** (see [Classes](#classes) below);
areas without visible corrosion are treated as background.

```
pip install ultralytics opencv-python numpy
```

Download the dataset from the Figshare link above and place the images and
masks under `dataset/train/` and `dataset/test/` following the structure
shown above (`images/` and `masks/` per split) before running
`masks_to_yolo.py`.

## Pipeline

You can go directly to the "4. Inference — run_corrosion_classification.py" section and run the trained model saved here.
Alternatively, you can train your own model following the instructions provided in this document.

### 1. `masks_to_yolo.py` — convert masks to YOLO segmentation labels

The VT dataset ships corrosion masks as single-channel (grayscale) PNGs,
where each corrosion severity is encoded as a specific pixel intensity:

| Pixel value | Class    | YOLO class id |
|---|---|---|
| 38  | Fair   | 0 |
| 75  | Poor   | 1 |
| 113 | Severe | 2 |

For each mask, the script:
1. Isolates each class via a binary threshold on the pixel value.
2. Finds external contours per class with OpenCV (`cv2.findContours`).
3. Discards contours with area < 20 px (noise removal).
4. Simplifies each contour with `cv2.approxPolyDP` (epsilon = 0.2% of the
   contour perimeter) to reduce the number of polygon points.
5. Normalizes contour coordinates to `[0, 1]` and writes one line per
   instance to `dataset/<split>/labels/<image_name>.txt`, in the YOLO
   segmentation format: `<class_id> x1 y1 x2 y2 ... xn yn`.

Run it from the project root (it expects `dataset/train/masks` and
`dataset/test/masks` to already exist):

```
python masks_to_yolo.py
```

### 2. `corrosion.yaml` — dataset config

```yaml
path: dataset
train: train/images
val: test/images

names:
  0: fair
  1: poor
  2: severe
```

### 3. Training

Training was run with the Ultralytics CLI/Python API using
`yolo11n-seg.pt` (YOLO11 nano, segmentation variant) as the starting
checkpoint:

| Setting | Value |
|---|---|
| Task | segment |
| Base checkpoint | `yolo11n-seg.pt` |
| Data config | `corrosion.yaml` |
| Epochs | 50 |
| Batch size | 8 |
| Image size | 512 |

Example command:
```
yolo segment train model=modelos/yolo11n-seg.pt data=corrosion.yaml epochs=50 batch=8 imgsz=512
```

Ultralytics writes checkpoints and training plots to a `runs/segment/...`
folder; the final `best.pt` / `last.pt` weights and training plots used by
this project were copied into `modelos/`.

**Final validation metrics (epoch 50, from `results.csv`), mask task:**

| Metric | Value |
|---|---|
| Precision (mask) | 0.182 |
| Recall (mask) | 0.310 |
| mAP50 (mask) | 0.140 |
| mAP50-95 (mask) | 0.050 |

These numbers are modest, which is expected given the small dataset size
(~400 images), the small model (nano), and a relatively short training run
(50 epochs) — the DeepLabV3+ baseline reported by the dataset authors
(F1 86.67) uses a full-size segmentation model rather than a lightweight
detector-based one. Possible next steps to improve these numbers: more
epochs, a larger YOLO11-seg variant (s/m/l), heavier augmentation, or
tuning the `epsilon` contour simplification in `masks_to_yolo.py` (an
overly aggressive simplification can distort small/thin corrosion regions
before they ever reach the model).

### 4. Inference — `run_corrosion_classification.py`

Runs the fine-tuned model (`modelos/weights/best.pt`) on a single image, a
single video, or an entire folder of images/videos.

```
python run_corrosion_classification.py <media_path_or_folder> <output_folder>
```

- If `<media_path_or_folder>` is a **file**, it must be an image
  (`.jpg .jpeg .png .bmp .tiff .tif .webp`) or video
  (`.mp4 .avi .mov .mkv .wmv .flv .webm`).
- If it is a **folder**, every supported image/video inside it is
  processed automatically (YOLO's `predict` natively accepts a directory
  as its `source`). Processing uses `stream=True` to avoid accumulating
  all results in memory at once, which matters for folders with many
  files or long videos.
- Results (annotated media, saved via Ultralytics `save=True`) are written
  under `<output_folder>/<timestamp>_<name>/`.

## Classes

| id | name | description |
|---|---|---|
| 0 | fair   | Early-stage corrosion |
| 1 | poor   | Moderate corrosion |
| 2 | severe | Advanced/severe corrosion |

The dataset's fourth category, *good* (no corrosion), is not included as a
model class — it corresponds to background / no detection.
